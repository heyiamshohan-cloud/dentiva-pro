## v1.3 implementation inventory

- Patient profile now exposes status, age, important alerts, preferred contact, normalized tags, configured custom patient fields, appointments, payments, follow-ups, notes and patient audit; save validation requires a name, phone input and valid email shape.
- Treatment plans now retain diagnosis/goal, procedures, teeth, duration, estimates, discount, estimated total, expanded statuses, responsible dentist and stage progress.
- Appointments retain rooms alongside dentist/chair/duration context; overlapping resource confirmation identifies the shared dentist, chair or room.
- Prescriptions retain the original first-medicine fields and support additional line-based medicines for print and record history.
- Dashboard remains command-center oriented and now supports local widget visibility, ordering and reset preferences; the global command palette includes analytics, reports, settings, payments, expense, backup and restore actions.
- Analytics reports collected/billed/expense/net/completion/no-show measures, six-month trends, payment mix and clinical/commercial insight cards without inventing targets or clinical recommendations.
- Notifications combine due invoices, low stock, expiry, queue wait, clinical follow-up and stale-backup signals; local category rules can be muted, read state persists, and notification actions open relevant pages/records.
- Diagnostics shows local storage, schema, record counts, relationship errors, attachment issues, backups and local account state; integrity checks are still mutation-audited.
- Settings persist rooms, custom patient fields and session timeout controls. Room records are normalized for backup/restore integrity while appointment forms use the configured room names.
- Backup/restore module groups now include the new catalog/rules/room collections, and migration preserves future schemas without silent downgrade.
- Financial statement UI and print output use the same deterministic `statementEntries` projection instead of maintaining a second balance formula.

## Release gates and non-negotiable boundaries

- No sample/demo/test data is shipped or seeded.
- Offline/local operation, light-only UI, Bangladesh defaults, safe money calculations, relational clinical history, attachment validation, auditability and migration/backup/restore integrity remain required.
- No mandatory cloud, telemetry, paid API, fake AI diagnosis, automated prescribing or medical recommendation is introduced.
- Windows portable, installer, ZIP and checksum verification remain mandatory. The installed-app launch/restart/uninstall sequence is intentionally not an automated blocker.
- Windows CI run `35708916503` passed tests/build, six-viewport visual checks, packaging, PE inspection, portable persistence, ZIP inspection and checksum verification; the workflow uploaded the portable EXE, installer, ZIP and checksum outputs.
- Release must not be called final until the explicit publication workflow creates the new tag/release and the remaining human review boundaries are reported honestly.
