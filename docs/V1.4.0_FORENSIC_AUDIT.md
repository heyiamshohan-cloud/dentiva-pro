## 1. Executive summary

Dentiva Pro v1.4.0 is an Electron + SQLite (`node:sqlite`, WAL) offline desktop
clinic-management app with a layered architecture:

```
Chromium renderer (src/main.js, ~3,000 lines, light-mode-only design system)
  → typed preload bridge (single generic invoke, channel allowlist)
  → Electron main process (electron/main.mjs) — session + RBAC ctx enforced per call
  → shared service layer (src/ops.js 61 ops + src/queries.js 40 queries)
  → repo-sql.mjs over electron/lib/db.mjs (transactional, payloads + typed columns)
  → backup/migration engines (backup.mjs, migrate.mjs)
```

**Verified strong (real, tested live):** storage engine integrity, relational schema with
FK enforcement and unique constraints, integer-cents financial engine with overpayment
reprice/lock guards, RBAC + auth (PBKDF2‑210k, timing‑safe, server‑enforced), backup
create/validate/restore with SHA‑256 manifests and tamper rejection, v4→v5 migration with
quarantine and preservation, scale behavior to **100k patients / ~945k records / 442 MB**
(live rerun), zero‑cap design (no record/DB-size limits).

**Verified weak/absent (user-visible):** printing from the packaged app **silently does
nothing** (PDF is generated and discarded; no print dialog/preview); the derived
notifications engine is dead code (page stays empty); no automatic backup scheduling;
no global audit log surface; 7 backend-only capabilities (waitlist, custom fields,
treatment templates, progress tracking, forensics, request log, signature data);
documentation contains claims that are false for the packaged product.

**Answer to the core question** ("installed in a real clinic for years with very large
data — what is reliable, incomplete, or could fail?"):

- **Reliable:** patient/clinical/financial/inventory data CRUD, money math, RBAC,
  backup/restore/migration, search/list performance at 100k+, corruption recovery paths.
- **Incomplete:** notifications/reminders, operational printing (receipts etc. from the
  app on Windows), audit-log visibility, waitlist UI, custom fields UI, backup
  automation, settings toggles that are dead (`notifications`, `showLogo`,
  `backupIntervalHours`…), Bengali UI completeness, analytics trend chart.
- **Could fail / degrade with time:** silent no-op printing (clinic believes a receipt
  printed); the op-level `payload`↔typed-column drift on rare paths; session/lock UX at
  shared reception machines relying on wait‑out lockout (no admin unlock); no tested path
  for >100k (SQLite fine, but unverified); Windows packaging unverifiable from CI (all
  recorded runs failed — §46).
